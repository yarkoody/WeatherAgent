# Web UI

React + TypeScript + Vite + Tailwind CSS 4 + shadcn/ui (style `base-rhea`, Base UI) with the AI Elements patterns from shadcn/ui, `@ai-sdk/react` 2 (`useChat`, AI SDK 5 UI message stream v1, which is what `ai` 0.9.0 for Python emits) and shadcn Chart (Recharts 3).

## Run

```bash
npm ci
npm run dev:mock   # no backend: replays streams recorded from the real backend (src/mocks/*.sse)
npm run dev        # real backend: proxies /chat, /scores, /hubs, /health to http://localhost:8000
npm test           # vitest
npm run build      # outputs web/dist, which FastAPI serves at /
```

## AI Elements used (shadcn/ui, copied into the repo)

- **Chat**: `ChatView.tsx` (Message Scroller, Message, Bubble, Empty).
- **Tool**: `components/ai-elements/tool-steps.tsx` (Trace), one row per tool part, expandable to show its arguments.
- **Suggestion**: `components/ai-elements/suggestions.tsx`, the four example questions.
- **Inline Citation**: `components/ai-elements/inline-citation.tsx` (Hover Card); each figure cites the tool that returned it.
- **Prompt Input**: `Composer.tsx` (Input Group). shadcn/ui has no speech-input pattern, so the mic is a Web Speech API button, as the shadcn docs suggest.
- Not used on purpose: Reasoning and Chain of Thought (model text is never streamed).
- shadcn primitives live in `src/components/ui/` (generated by `npx shadcn@latest add ...`; config in `components.json`).

## How it renders

- `POST /chat` streams tool parts, then exactly one `data-answer` part (a `ChatResponse`). No answer text is streamed.
- Tool parts become progress chips, and each tool's output is drawn by its widget in `src/widgets/` ("generative UI"). Widgets read only tool output, never model text.
- The answer card renders `answer.answer` as markdown, the `figures` table, collapsible assumptions and data limits, and a grounding badge (pass, retried, failed). Out-of-scope and no-data answers have their own states.
- Grounding failed: figures are marked unverified, citations stop claiming a match, and read-aloud says "Unverified answer" first.
- Errors: 422, 429 (no retry offered) and 503 from `/chat` get their own message. A turn that ends without a `data-answer` (Stop, cut-off stream, reload mid-turn) shows its unfinished steps as stopped and a "No answer received" notice.
- Each widget and the whole thread sit inside error boundaries; restored history is validated loosely.
- Each request sends only the chat id and the newest user message (the server keeps the history).
- The chat id is the backend `session_id`. It and the messages are kept in `localStorage`. "New conversation" starts a new id.
- Voice: the mic uses the Web Speech API (disabled, with a tooltip, where unsupported); the speaker toggle reads each new answer aloud.

## Analyst and developer views

The default view is for analysts: plain-language progress steps, and figures with label, hub and value plus the grounding badge. Add `?debug=1` to the URL for the developer view (remembered in `localStorage`; `?debug=0` turns it off): a "Developer view" pill, source-tool citations on each figure, expandable tool names and arguments, the trace id and grounding errors.

Every score has an (i) button ("How is this calculated?"). It opens on click, tap or Enter. Its text is built only from the tool output (`src/lib/explain.ts`): each signal's raw value, unit, weight and contribution, then one line on the index (days ÷ `days_cap` × 100, bands at `medium_from_days` and `high_from_days`).

## JEV second opinion (Scores view)

`GET /second-opinion` feeds a "Second opinion (JEV)" column: per hub a four-square strip (winter, flood, hurricane, severe storm; filled = agrees, red outline = differs) and "3/4 agree"; click or tap shows each hazard's formula band against JEV's band and score. A summary line above the table gives the overall agreement, run date and data date, with an (i) explainer. A 404 hides all of it. Below 640 px the column collapses into a compact badge next to the hub name. In the developer view a "Re-run JEV" button calls `POST /second-opinion/rerun` and shows the server's detail on 503 (re-running works only locally). JEV never changes scores or rankings.

## Mocks

`src/mocks/chat-stream*.sse` were recorded from `app.agent.stream_turn` with `ai.testing.FakeModel` and the real tools (NWS alerts stubbed). Scenarios: ranking, compare, weather, alerts, no data, out of scope, and failed grounding (ask "How exposed is Houston?"). `scores.json` is the real `/scores` output. `second-opinion.json` is synthetic (real formula bands, made-up JEV scores with six deliberate disagreements); the mock re-run returns 503. The mock transport is the real `DefaultChatTransport` with a replaying `fetch`, so the mocks go through the same parser as the live stream. Mock code is dropped from production builds.
